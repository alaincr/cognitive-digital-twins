# ADR-001 — Doctrine unique : log-SSOT, Roam-surface, supersession des strates 1–4

**Statut :** RATIFIÉ (par le propriétaire, 2026-07-04 — ratification
communiquée en session ; consignée ici le même jour).
**Date de proposition :** 2026-07-04.
**Contexte détaillé :** `SYNTHESE_analyse_critique.md` §4.2–4.3 et §8.
**Bloque :** tout le pack PRD (chemin critique de `00_gap_analysis.md` §3).

---

## Contexte

Le dépôt contient quatre doctrines opérationnelles simultanées (vault plat,
wiki Roam/CLAUDE.md, organisation Paperclip 22 agents, stack Mnemosyne) sans
qu'aucune ne supersède officiellement les autres. Deux contradictions sont
bloquantes pour les développeurs : (1) « Roam est la vérité » (CLAUDE.md)
contre « le log append-only est la vérité » (SPEC-00 §1) ; (2) orchestration
par agents-heartbeats contre behaviors + juges + consolidateur unique.

## Décision

1. **Le journal d'événements append-only de Mnemosyne
   (`store/events.jsonl`) est la source de vérité épistémique.** Roam est
   la **surface de capture et de restitution humaine** : son export est un
   intrant (brique B1), l'espace `M/*` sa projection (brique B2). Le
   CLAUDE.md du dépôt est amendé en conséquence (sa ligne « Roam is the
   truth, the repo is the spec » devient « le log est la vérité, Roam est
   la surface, le repo est la spec »).
2. **L'organisation Paperclip (22 agents) est supersédée** par
   behaviors + juges + consolidateur. Les configs `agents/` sont archivées
   comme matériau de la strate 3. Toute résurrection exige un nouvel ADR.
3. **Le raisonnement vit hors-process** (L1 sur le graphe). Les analyses
   Live-AI / RLM-Graph de mai sont closes par cette décision.
4. **Le wiki plat (`wiki/`) et les pages bootstrap sont des archives** et
   des intrants de migration. Aucune ingestion n'y reprend.
5. **La charge de travail directrice de la boucle réduite est le corpus
   RGPD/thèse du propriétaire.** Toute extension de périmètre attend M0
   (rapport `first_judge_report.md`) + 4 rapports hebdomadaires B7.
6. **Gel de design** : aucune nouvelle session d'architecture tant que M0
   n'existe pas. La prochaine session utile se termine par un chiffre.

## Conséquences

- Les développeurs des briques B1–B7 implémentent contre UNE doctrine ;
  toute spec contredisant ce document est réputée historique.
- Coût accepté : les strates 1–4 ne seront ni maintenues ni terminées ;
  leur valeur est celle d'intrants de migration et d'historique de design.
- Si non ratifié : toute session future peut légitimement relancer un
  pivot (cinquième → sixième strate), et le pack PRD n'a pas de fondation.

## Annexe A — Portée exacte du point 3 : exécution vs projection des traces

**Ajoutée le 2026-07-04, suite à un échange avec le propriétaire.** Cette
annexe précise le point 3 ; elle n'en modifie pas la décision.

### A.1 Ce que le point 3 tranche — et ce qu'il ne tranche pas

Le point 3 tranche **où le raisonnement s'exécute** : hors-process, dans le
moteur L1 (RLM) naviguant le graphe. Il ne tranche PAS **où les traces de
ce raisonnement sont restituées**. Le RLM n'est donc pas abandonné : c'est
l'option retenue (le camp « RLM-Graph » de mai gagne, « Live-AI » est clos).
Il est seulement **différé** : la boucle réduite ne fait tourner que les
micro-juges ; le driver compose/RLM est exclu de la Phase 0 (SPEC-00 §6,
PRD B2 non-objectifs, PRD B7/E3 v0 sans génération) et se débloque après
M0 + 4 rapports hebdomadaires (point 5).

### A.2 Intention du propriétaire (consignée)

> Le RLM doit raisonner essentiellement sur Roam, et les étapes doivent
> être consignées au niveau des blocs concernés — par exemple enregistrer
> qu'un bloc a été parcouru dans le contexte de telle recherche — pour que
> ces traces s'accumulent comme information.

Cette intention est **compatible avec la présente décision** : le graphe
que le RLM navigue *est* le contenu de Roam (via B1), et les traces se
projettent dans Roam (via B2) sans que le calcul y vive. Le mécanisme Roam
qui rattache une trace « au bloc concerné » sans le modifier est la
référence liée : un bloc écrit sous `[[M/Research/<slug>]]` contenant
`((uid))` rend la trace visible dans le panneau de linked references du
bloc visité — I1 (jamais d'édition des blocs utilisateur) est préservé.

### A.3 Mécanique retenue pour la phase 2 (esquisse normative)

- Deux nouveaux types d'événements au journal :
  `rlm.visited` (haut volume — chaque lecture ; jamais projeté vers Roam,
  requêtable dans le log) et `rlm.cited` (basse fréquence — blocs ayant
  matériellement contribué à la réponse ; projeté).
- Projection : `kind: trace` dans `writeback_orders.jsonl`, template
  `trace_v1`, une page par épisode de recherche `M/Research/<slug>`
  (déjà couverte par l'allowlist `M/*` de B2), budget ≤ 30 refs projetées
  par épisode.
- Accumulation machine : les `rlm.visited` alimentent `:prop/activation` /
  `:prop/last-touched` (schéma zettel existant) — la salience côté système
  et la visibilité côté humain sont deux consommateurs du même événement.

### A.4 Garde-fous (conditions de l'annexe)

1. **Grain de projection** : jamais un bloc Roam par *hop* de traversée ;
   la trace projetée est au grain de l'épisode de recherche, filtrée sur
   la contribution effective. La traversée exhaustive vit dans le log.
2. **I1 non négociable** : aucune trace inline (ni attribut ni enfant)
   dans un bloc utilisateur ; uniquement des backlinks depuis `M/*`.
3. **Pas de rétroaction** : les pages `M/Research/*` sont couvertes par
   l'exclusion `M/*` du harvest/préfiltre/embeddings — le système ne
   re-moissonne jamais ses propres traces comme contenu.

### A.5 Suite

À spécifier comme brique de phase 2 (`PRD_B8_trace_projection`, même
format que le pack) une fois la boucle réduite fermée. Toute demande de
traces *inline* dans les blocs utilisateur exigerait d'amender I1 — donc
un nouvel ADR, déconseillé.
